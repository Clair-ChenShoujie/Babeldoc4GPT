# Babeldoc4GPT

**在 ChatGPT Work 中翻译 PDF，尽量保留原文的公式、表格与版式，并生成便于对照阅读的双语 PDF。**

阅读外文论文或技术资料时，除了看懂文字，也需要让公式和图表与正文对应。Babeldoc4GPT 将当前对话模型的翻译能力与 BabelDOC 的 PDF 解析、排版能力结合起来：上传文档、说明语言和页码，即可在 Work 云沙箱中完成翻译与文件生成，无需在自己的电脑上部署服务。

默认使用当前对话完成翻译，**不需要额外的翻译 API Key**。项目也保留了可选的 OpenAI 兼容 API 模式，只有明确选择时才使用。

[下载 BabelDOC-Cloud.zip](https://github.com/Clair-ChenShoujie/Babeldoc4GPT/releases/download/v0.2.0/BabelDOC-Cloud.zip)

## 适合用来做什么

- 阅读外文论文、技术文档和报告，希望在译文中继续查看公式、表格和原有页面结构。
- 同时获得目标语言 PDF 与原文／译文对照 PDF，方便阅读和核对。
- 先试译几页，再决定是否处理全文；长文需要时可以暂停、保存进度，之后继续。

这是一个 **Work 云端工作流包**，需要在支持代码执行和文件处理的任务环境中使用。

## 开始前需要什么

1. **能够执行代码、处理附件并返回文件的 ChatGPT Work 云沙箱。** 安装器面向 Linux x86_64，支持 Python 3.11–3.13，包内验证使用 Python 3.12。
2. **首次运行所需的网络访问。** 包内含引擎源码；Python 依赖、排版模型和字体需要在沙箱中另外下载。
3. **一份可读取的 PDF。** 建议先用有文字层的文档试译；加密文档需要先提供已解锁的副本。

ChatGPT 服务费用与使用额度仍按账号适用条件执行。可处理的文档规模和耗时，取决于账号能力及沙箱的网络、内存和执行时间。

## 下载与使用

### 方式一：导入为插件

1. 从 Releases 下载 [BabelDOC-Cloud.zip](https://github.com/Clair-ChenShoujie/Babeldoc4GPT/releases/download/v0.2.0/BabelDOC-Cloud.zip)。请选择这个安装包，GitHub 自动生成的 Source code 压缩包用于获取仓库源码。
2. **如果你的 ChatGPT 界面提供插件 ZIP／文件导入入口**，通过该入口导入。
3. 在新的 Work 任务中启用 **BabelDOC 云端 PDF 翻译**，上传要处理的 PDF。
4. 发送下一节的试译请求。

导入入口的可用性以账号界面为准。如果你的账号没有该入口，可以尝试下面的单任务方式。

### 方式二：在一个 Work 任务中直接使用

将 `BabelDOC-Cloud.zip` 和 PDF 一起上传到具备上述能力的 Work 任务，然后发送：

```text
请在本次 Work 的云沙箱中解压 BabelDOC-Cloud.zip，读取其中的
skills/translate-pdf-cloud/SKILL.md，并按该工作流实际处理附件 PDF。

先将 PDF 的第 1–5 页从英文翻译成中文；不足 5 页则处理全部页面。
使用当前对话完成翻译，不调用额外模型 API，不连接我的电脑。
尽量保留公式、表格和版式，生成中文 PDF、双语 PDF 和可恢复的进度包，
完成后给我可下载的文件。若环境缺少必要能力，请报告具体原因。
```

这种方式仅在当前任务中执行工作流，**不会将插件安装到账号**；同样需要可执行代码、可准备依赖的云沙箱。

## 第一次使用：先试译 5 页

已导入插件的用户，上传 PDF 后可以直接发送：

```text
请用 BabelDOC 云端 PDF 翻译，将这份 PDF 的第 1–5 页从英文译成中文。
不足 5 页则处理全部页面。使用当前对话翻译，不调用额外模型 API。
尽量保留公式、表格和原版式，输出中文 PDF 和双语 PDF。
请实际执行，并检查代表性页面后给我下载文件。
```

将“英文”和“中文”替换成所需语言。这里的页码按 **PDF 文件中的实际页面顺序，从 1 开始**，不是正文印刷页码。

首次运行需要检查环境、安装依赖并准备资源。试译后，先检查正文与术语，再查看公式、表格和双栏页面是否错位，然后决定是否处理全文。

### 正式翻译

```text
试译结果可以，请按相同语言设置处理全文。
术语请保持一致，输出中文 PDF、双语 PDF；如果生成了术语表，也请一并提供。
如果任务需要暂停，请保存可恢复的进度包并给我下载，不要把未完成文件当作成品。
```

全文翻译可能需要新建任务，试译结果能否复用取决于请求是否匹配。长文也可以按 `1–20`、`21–40` 等页码分段处理，逐段检查并保存；需要合并时请另行说明。

完成后，主要文件包括：

| 文件 | 用途 |
| --- | --- |
| 目标语言 PDF（文件名通常含 `mono`） | 连续阅读译文 |
| 双语 PDF（文件名通常含 `dual`） | 对照原文核查译文 |
| 术语表 CSV（如有生成） | 查看、整理术语译法 |
| 进度 ZIP（按需导出） | 保存任务，供后续恢复；不是最终译稿 |

请及时下载结果和进度包，沙箱文件不宜作为长期存储。

## 长文、暂停与恢复

工作流会分批提交译文，并记录已经接受的结果。如果暂时不继续，可以说：

```text
请暂停当前任务，等当前执行步骤结束后导出可恢复的进度 ZIP，并给我下载。
```

继续时：

- **仍在原来的可用沙箱中：** 要求继续原任务，不要另建重复任务。
- **换了任务或沙箱：** 准备好工作流，上传之前保存的进度 ZIP，要求导入并继续。

```text
请导入这个 BabelDOC 进度包，继续原来的翻译任务。
复用已提交且匹配的译文，完成后输出目标语言 PDF 和双语 PDF。
如果进度包使用的是 API 模式，请先向我确认，不要直接调用付费 API。
```

进度包保存原始 PDF、任务设置、术语表及已提交的译文。跨沙箱恢复会重新解析原文，并复用匹配的结果；尚未保存的内容需要重新处理。请像保管原文一样妥善保管进度包。

## 遇到问题时

| 情况 | 建议处理方式 |
| --- | --- |
| 导入后没有加载工作流 | 尝试 ZIP 与 PDF 一起上传的单任务方式，并让 Work 读取包内 `SKILL.md`。 |
| 安装依赖、字体或模型失败 | 要求提供具体下载错误，确认沙箱网络是否允许访问资源。不要为了绕过安装失败而改用翻译 API。 |
| 单步执行超时或任务中断 | 先检查原任务状态和日志；在环境允许时调整单步时间后继续，避免反复新建任务。 |
| 提示译文格式校验失败 | 让工作流修复对应批次的段落 ID、公式占位符或格式，再提交。不要跳过校验直接交付。 |
| 排版错位、漏译或扫描件效果不佳 | 先缩小到有问题的几页复现并检查；必要时提供文字层更清晰的 PDF。 |
| 原沙箱文件已经丢失 | 上传已下载的进度包恢复；没有进度包时，不能保证找回已完成的译文。 |

反馈问题时，请附上语言、页码范围、使用方式和具体错误；如方便，可提供不含敏感内容的最小示例 PDF。请勿附带密钥。

## 隐私与 API 模式

**默认对话模式：** PDF 解析和排版在 Work 云沙箱中执行，待翻译内容由当前对话模型处理，脚本不另行调用外部翻译模型 API。文档会在云端处理，上传前请确认内容适合交给所用的 ChatGPT 服务处理。

**可选 API 模式：** 仅在你明确选择后使用指定的 OpenAI 兼容模型接口，待翻译内容会交给该接口处理，可能产生额外费用。密钥通过环境变量提供，不应粘贴到聊天、配置文件、进度包或问题反馈中。

进度包含原文和译文，分享它就可能同时分享文档内容。

## 效果与能力边界

目标是保留可读的文档结构，而不是保证逐像素复刻。复杂扫描件、特殊字体、密集表格、多栏排版和段落切分都可能影响结果；重要的数字、公式及专业表述仍应对照原文检查。

下载包内提供了可自行查看的两页测试材料：

- `tests/sample.pdf`：英文原文。
- `examples/`：对应的中文 PDF、双语 PDF 和术语表。

样例展示了公式、表格和双栏内容的处理形式，也保留了局部间距问题。包内验证来自 Linux 测试环境；你的文档和 Work 环境仍需通过首次试译确认效果。

<details>
<summary>进阶：实现与执行接口</summary>

当前工作流版本为 `0.2.0`，包含 BabelDOC `0.6.2` 和 PDFMathTranslate Next `2.9.0` 源码。普通用户通过自然语言使用即可，无需手动运行命令。

实现位于包内 `skills/translate-pdf-cloud/`，完整执行约定见该目录下的 `SKILL.md`。脚本以 UTF-8 JSON 文件接收参数，主要流程为：

```text
环境检查与依赖安装 → prepare_assets → create_job
→ advance → 当前对话翻译 → submit_results（循环）
→ 确认 completed → export_files
```

`export_checkpoint` / `import_checkpoint` 用于导出和恢复进度；`get_status` 用于查看状态。没有待翻译请求不等于任务完成，PDF 仅在引擎完成后导出。

代码支持另行提供离线模型、字体及匹配的依赖 wheels；Releases 中的普通安装包不含这些资源。
